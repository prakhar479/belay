$ curl -fsSL https://prakhar479.github.io/belay/install.sh | sh
$ cargo install --git https://github.com/prakhar479/belay belay-cli

01 The gap

Brilliant inside one conversation. Blind outside it.

Your coding agent only knows what's in front of it right now. So it forgets yesterday, grades its own work, runs whatever it decides to, and keeps no record. You've probably watched each of these happen.

› carry onwhat were we doing?the last session's work, gone

Every session starts from zero.

Yesterday the agent tracked the bug down, then ran out of room. Today it starts over, reading the same code again as if it had never seen it.

- assert total == 19.99+ assert total == 19.98

The test was right. The agent changed it.

The code gave 19.98. The test said it should be 19.99. The easiest way to make the test pass? Change the test.

edit → run → assert 500 == 200edit → run → assert 500 == 200edit → run → assert 500 == 200

Third fix. Same failure.

Edit, run, fail. Edit, run, fail. Same error every time, and the agent keeps trying the same kind of fix.

$ ./setup.sh~/.ssh · ~/.aws · ~/other-repoall of it in reach

A script you did not read.

The agent runs commands as you. Your SSH keys, your cloud logins, your other projects: all one command away.

None of that is the model's fault: a single conversation simply can't hold it. belay is the part of your setup that lives outside the conversation. It sees across sessions, across time, and across agents, and it answers to you.

02 It remembers

Work never starts from zero.

Close your laptop tonight, open a new session tomorrow, and the agent already knows where things stand. The same goes for a long conversation that gets compacted, or one you --resume.

A handoff, without asking.

When a session ends, belay writes a short note for the next one: what the task was, which files changed, how the last test run went, and what is still broken. It writes it from what actually happened, not from what the agent says happened. If the agent left a note of its own, that goes at the end, marked as the agent's.

  • A good startEach new session gets the last note, plus the few memories that matter most for this project. It is kept short, so it does not crowd out real work.
  • Nothing lost in compactionWhen Claude Code squeezes a long conversation down, belay hands the essentials back: the task, the open failure, and anything it blocked.
  • Resume means resumePick a conversation back up with --resume, -c, or /resume, and belay picks up right where it was too.
  • belay memoryLook through what belay remembers, search it, or add your own. Every memory says who wrote it: belay, the agent, or you.
  • Yours to approveAn agent's memory waits for you. Only you run belay memory approve or drop.
  • Works with what you havebelay never touches your CLAUDE.md or Claude Code's own memory. It reads them so it does not repeat what the agent already knows.

03 It's honest

Done means actually done.

An agent can't grade its own work. belay sees each step, and what came back, before the agent does, so a bent test, a loop, or an unchecked "done" doesn't slip past.

Test guard

Edits that weaken tests wait for you.

Before the agent changes a test, belay compares the old and new versions. If the change makes the test easier to pass rather than the code better, the edit is held until you say it is fine.

  • ✕An assertion is removede.g. - assert total(cart) == 19.99
  • ✕A skip marker is addede.g. + @pytest.mark.skip
  • ✕An expected value becomes the failing run's actual value19.99 → 19.98
  • ✕A tolerance is raisede.g. abs=1e-6 → abs=0.5
  • ✕An assert is always truee.g. assert True
  • ✕A command rewrites snapshot or golden filessnapshots · golden files

Only you can let it through. The agent can't approve its own edit.

Protect anything. Add paths you care about to .belay.toml.

Prefer a gentler touch? Set guard = warn: the edit goes through, and the agent is told why it looks suspicious.

Loop detection

Three rounds. Same failure. One message.

belay recognizes the same failure even when the details shift (a different line number, a different temp path). After three tries with no progress, it tells the agent, once, to step back. And if the agent tries to call it done after changing code it never re-tested, belay asks it to run the tests first.

  • 2assert 500 == 200
  • 3assert 500 == 200

04 It's safe

Bold work, safely.

Try the risky thing somewhere it can't hurt you. And when you add a skill from the internet, see what it says before your agent does.

Sandboxes.

A sandbox is a walled-off copy of your project. Run one command in it, a whole agent session, or a task you leave running. Whatever happens inside stays inside. The work comes back to you as a git branch: read it, and merge it if you like it.

  • Walled offIt can't see your SSH keys, cloud logins, other projects, or Docker. On WSL it can't reach Windows either.
  • Honest about the networkIt uses your normal internet connection. Anything your machine can reach, the sandbox can too.
  • Can't run awayIt has limits on memory, processes, disk and time. Hit one, and belay stops it and tells you which.
  • Safe or nothingIf a proper sandbox can't be built on your machine, belay won't pretend: it runs nothing. Linux only for now.
  • belay sandbox doctorDon't take our word for it: this tries to break out of a fresh sandbox and tells you if anything gets through.

What it protects, and what it does not: the threat model.

belay sandbox
$ belay sandbox run -- make test         # a command; its changes land on a branch
$ belay sandbox claude                   # a whole Claude Code session, supervised from outside
$ belay sandbox task "add tests for parse_size"   # a headless follow-up
$ belay sandbox show fix                 # branch, commits, audit, limit stops
$ belay sandbox diff fix                 # what the branch changed
$ git merge belay/sandbox/fix            # take the work, once you have read it

Skills from URLs.

A skill is a set of instructions your agent follows from then on, so adding one from a stranger deserves a look first. belay downloads it, checks it, and shows it to you. Nothing is active until you approve it.

  • Look firstSee its name, its files, and any warnings. Looking installs nothing.
  • Checked for tricksbelay flags things like hidden characters, encoded blobs, scripts that download and run code, and text telling the agent to switch belay off.
  • No surprises laterIt is pinned to the exact version you saw. If its files change afterwards, belay notices.
  • You decideYour agent can suggest a skill, but only you can approve it.
belay skill
# look; this installs nothing
$ belay skill preview https://github.com/o/r/tree/main/skills/pdf
# preview, confirm, install (an agent's add only stages)
$ belay skill add https://github.com/o/r/tree/main/skills/pdf
$ belay skill list            # installed, waiting, drift
$ belay skill approve pdf     # yours to run

05 It's clear

You always know what happened, and why.

Each time the agent is about to do something, Claude Code checks in with belay. belay answers in a couple of milliseconds, usually with "carry on", and keeps a record of everything it did, so you can always ask why.

1 · The agent

Claude Code

Checks in with belay before and after each step.

2 · The messenger

belay hook

Passes the question along. If anything goes wrong, it simply stays out of the way.

3 · The watcher

one per session

Keeps track of how the session is going.

4 · The judgment

belay

Decides: is this test change fair? Is it going in circles? What should it remember?

5 · The record

a log

Writes down everything it did, and why.

← The agent gets an answer: go ahead, stop, or "here's something you should know". You get a short note too, which the agent never sees.

You see what it did.

When belay does something that matters, you see a one-line note in Claude Code. By default that's only the important stuff; set report = normal or verbose if you'd like to see more.

Everything can be switched off. belay pause turns belay off for this session, or just one part of it. Only you can do that; the agent can't switch belay off on its own.

There are no modes to choose from: belay just works.

07 The deal

Built to stay out of the way.

A safety net should never be the thing that trips you up.

Fast

~2ms

About 2 ms per step. You won't notice it.

We hold ourselves to 20 ms, and stay well under it.

2 msbudget 20 ms

Never in the way

250ms

250 ms, and then it lets go.

If belay hits a problem, or takes longer than a quarter of a second, it steps aside and Claude Code carries on as if belay weren't there.

Local

0

0 model calls.

No AI calls, no telemetry. belay only goes online when you ask it to, like fetching a skill. Everything it keeps stays on your machine, with passwords and keys blanked out.

Prompt cache

Never

Never rewrites history.

belay only adds to what comes next; it never changes what the agent has already seen. That keeps things fast and cheap.

Yours to approve

You

You approve what lasts.

Anything that lasts, or that lifts a safeguard, is yours to say yes to: letting an edit through, pausing belay, undoing work, keeping a memory, approving a skill. The agent can't do those for you.

One binary

1

1 Rust binary.

One small program does everything. Install it with one command, and remove it just as easily.

08 Get started

Try it in a minute.

One command sets everything up. After that, just use Claude Code the way you already do. belay stays quiet until it has something worth saying, and when it does, it tells you exactly what you can do about it. There's nothing to memorize.

quick start
  1. $ curl -fsSL https://prakhar479.github.io/belay/install.sh | shChecks the download, installs to ~/.local/bin, adds the Claude Code plugin. Read it first.
  1. $ cargo install --git https://github.com/prakhar479/belay belay-cliRust 1.87 or newer.
  2. $ belay installThe Claude Code plugin. It shows each change and asks first.
  1. $ belay doctorIs everything in place? One line per check, with the fix.
  2. $ claudeWork as usual. belay is there when it matters.
