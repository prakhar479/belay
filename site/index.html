Your agent climbs. belay holds the rope.

A local supervisor for Claude Code. It sees every tool call, and its output, before the agent reads it. It guards your tests, catches loops, trims long test output, and writes down why.

$ cargo install --git https://github.com/prakhar479/belay belay-cli
$ claude plugin marketplace add prakhar479/belay
$ claude plugin install belay@belay

Rust 1.87+. Or get a binary from Releases. Then run belay claude instead of claude.

01 The problem

You have watched this happen.

Coding agents are fast. They also take shortcuts you only notice later.

- assert total == 19.99+ assert total == 19.98

The test was right. The agent changed it.

The code returned 19.98. The test expected 19.99. The quickest way to green was to edit the test.

edit → run → assert 500 == 200edit → run → assert 500 == 200edit → run → assert 500 == 200

Third fix. Same failure.

Edit, run, fail. The error never changes. The agent keeps going anyway.

300 passed · 2 failed334 lines · 6,407 tokensall of it in context

Two failures in 334 lines.

Every passing line lands in the context. The two that matter are buried in the rest.

shop-1 edits shop/payments.pyshop-2 edits shop/payments.pyneither one knows

Two sessions, one file.

Another session changed the file. Yours is still working from an old read.

belay catches each of these moments. In optimize mode, it tells the agent in time.

02 What it does

It watches every move. It catches the fall.

belay sees each tool call, and its output, before the agent reads it. Here is what it does with that.

Test guard

Edits that weaken tests wait for you.

Before an Edit or Write lands in a test file, belay compares the old and new text. It flags six things. In optimize mode, the edit is denied until you allow it.

  • ✕An assertion is removede.g. - assert total(cart) == 19.99
  • ✕A skip marker is addede.g. + @pytest.mark.skip
  • ✕An expected value becomes the failing run's actual value19.99 → 19.98
  • ✕A tolerance is raisede.g. abs=1e-6 → abs=0.5
  • ✕An assert is always truee.g. assert True
  • ✕A command rewrites snapshot or golden filessnapshots · golden files
AgentEdit a test
→
belayDenied
→
You! belay allow
→
AgentRetries the same edit

Only a human can allow it. The allow comes from your ! shell line, never from the agent.

Protect any path. List it in .belay.toml.

In look mode, the edit goes through. belay records the flag and what it would have done. The agent sees no difference.

Loop detection

Three rounds. Same failure. One message.

It matches failures by a normalized signature. It also catches edit cycles: edit, revert, edit. It tells the agent once.

3of 3
  • 1assert 500 == 200
  • 2assert 500 == 200
  • 3assert 500 == 200

Told once A different approach may be needed.

Ledger with reasons

Every action has a reason.

Every session is recorded. Each action carries a one-sentence reason and the chain of causes behind it.

belay reportthe whole session
belay why a-2one action, its reason and causes
belay flagnote a mistake belay made

Learned fixes

A fix found once is not lost.

When a failure is fixed and the full suite passes, belay keeps the change. The next session in that project that hits the same failure is told how it was fixed, with the diff.

03 How it works

Between the hook and the agent.

Claude Code calls a hook on every tool call. belay answers in about 2 ms, or it stays quiet. Either way, it writes down what it saw.

1 · Hook

Claude Code

Calls belay before and after each tool call.

2 · Shim

belay hook

A thin shim. It only forwards. On any error it prints nothing.

3 · Daemon

daemon

One per session. It keeps the session's state.

4 · Core

core

Decides: guard, loops, summaries, messages.

5 · Ledger

ledger

Records every action with a reason.

← Look mode: no response. The agent sees no difference. Optimize mode: the decision goes back to the agent. A deny, a message, or a summary.

Two modes. Start in look.

Look mode is the default. belay records everything and decides what it would do. The agent sees no difference.

In optimize mode, the same decisions reach the agent. Switch when the report looks right to you.

look and optimize, side by side
look defaultoptimize opt in
LedgerEvery decision, with its reasonEvery decision, with its reason
Hook answerNone. belay never answers a hook.The decision
Agent seesNo differenceDenied edits, summaries, loop notes, peer news

05 Principles

Built to stay out of the way.

A supervisor should never be the thing that breaks your session.

Fast

~2ms

About 2 ms per hook, at p95.

The budget is 20 ms, and CI measures it.

2 msbudget 20 ms

Fails open

250ms

250 ms, and then it lets go.

On any error, or a timeout over 250 ms, the hook prints nothing. The agent goes on.

Local

0

0 network calls. 0 model calls.

Secrets are redacted before anything is written.

Prompt cache

Never

Never edits the past.

belay acts only on what the agent has not seen yet. The prompt cache stays intact.

One binary

1

1 Rust binary.

The hook, the daemon and every command ship as one binary. Build it with cargo, or take one from Releases.

Tested

474

474 tests, plus fuzz targets.

128CLI
57end-to-end, fake agent

06 Quick start

Start with sessions you already ran.

belay retro --all reads your old transcripts and changes nothing. Then run one session in look mode, and read the report.

quick start
  1. $ cargo install --git https://github.com/prakhar479/belay belay-cliRust 1.87+. Or a binary from Releases.
  2. $ belay doctorCheck the setup.
  3. $ belay retro --allWhat belay would have caught in sessions you already ran.
  4. $ belay claudeYour next session, in look mode. All args go to claude.
  5. $ belay reportWhat it saw, and what it would have done.
  6. $ belay claude --belay-mode optimizeWhen you agree with it, let the decisions reach the agent.
  1. $ claude plugin marketplace add prakhar479/belayAdd the marketplace.
  2. $ claude plugin install belay@belayInstall the plugin.
