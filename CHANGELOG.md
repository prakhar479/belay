# Changelog

## 0.2.0

belay 0.2 has no modes: it acts within what the agent supports, and tells you what it did. It adds:
- memory that carries a session over to the next one, a compaction, or a `--resume`;
- a more precise test guard, and verify-before-done;
- `belay brief`, `belay usage`, and notifications;
- sandboxes and background sessions;
- skills from URLs.

Install it with one command: `curl -fsSL https://prakhar479.github.io/belay/install.sh | sh`. Configs from 0.1 still load; `belay config migrate` rewrites them. Ledgers from 0.1 still read.

### Added

- **Getting told when you are needed** (`notify = attention`, now the default): belay notifies you when it blocks an edit, steers a loop, the agent stops with its tests unmet, a turn ends and stays idle for a minute, or Claude Code waits on a permission prompt or a question. Notifications go to the desktop, a terminal bell under `belay claude`, and `notify_command` (new key: your command gets the event as JSON on stdin and is stopped after 5 s, never delaying a hook). At most one per kind per session every 2 minutes; `notify_quiet = HH:MM-HH:MM` holds them. `notify = all` adds every warning; `off` stops them. The old `notify = true|false` reads as `all|off`, and `belay config migrate` rewrites it. belay now hooks Claude Code's `Notification` event (plugin and `belay claude`), recorded as a new ledger event `agent_waiting` (additive; older belay versions skip it).
- **`belay bg`: background sessions that keep working when you leave.** `belay bg start "<prompt>"` runs the agent headless on the prompt, detached from your terminal, in a sandbox when one can be built here (its work lands on `belay/sandbox/<id>`), else in this checkout with the guard on (`--sandbox`, `--here` choose). `--resume <conversation>` starts from a fork of it, so the original stays yours. `--budget 2M|$5` and `--until 18:30|2h` stop it at the next step and say so. At a usage limit it waits and goes on by itself 2 minutes after the reset. It holds the machine awake for its life (`--no-keep-awake` not) and prints what a closed lid does here. `belay bg list | status | watch | stop | attach`: `status` shows the phase (working, waiting until HH:MM, done, needs you: why, stopped: why), tokens and cost, and the last notice; `attach` stops it and opens its conversation through `belay claude --resume` (or `belay sandbox claude --id … --resume`), so tracking goes on. Notifications (desktop, `notify_command`) for done (with the brief's first lines), needs you, usage limit, budget, and deadline. Agents may start one with the new MCP tool `bg_start` (always sandboxed, within `sandbox_task_tokens` and `sandbox_tasks_per_hour`); `bg stop` and `attach` are the user's, and denied to the agent. State in `<belay home>/bg/<id>/`.
- **`belay config`** prints every config key, its value, and where it came from (the file and line, or the default). **`belay config migrate [--yes]`** rewrites 0.1 keys and `look` values in place, keeping comments and order: it shows a diff, asks, and keeps a backup (`config.toml.bak-<unix time>`). The 0.1-key warning is now one line that names `belay config migrate`, at most once a day per config file (again when the file changes), and never from `belay hook` or `belay status`. When a file sets both an old and a new name (`fleet` and `awareness`), the new one now wins.
- **When belay is wrong, say so in one command.** Every warning ends with "Wrong? `belay flag a-N`", in Claude Code, `belay watch`, and the exit summary ("2 warnings · flag any that were wrong: `belay flag a-7`"). `belay flag` with no id flags the newest warning, and the note is optional. `belay review` groups flags by rule (guard rule, `loop`, `cycle`, `verify`), newest first, with each action's reason and a command to save it as a fixture. `belay export --action a-N --fixture <dir>` writes the edit's before and after, or the outputs, cleaned, with a README; review it before you publish it. The agent may flag a warning it thinks wrong: its flags are labelled `agent` and shown apart; a flag lifts nothing. `belay report` lists the session's flags and counts warnings without one. Flags gain a `by` field (`user` or `agent`); older flags read as the user's.
- **Guard feedback:** when you `belay allow` blocks of the same guard rule twice in a session, that rule only warns for the rest of the session, and `belay allow` says so. `belay resume guard` makes it deny again. Recorded as `feature_changed` on `guard:<rule>`.
- **One-command install:** `curl -fsSL https://prakhar479.github.io/belay/install.sh | sh` downloads the binary for your machine from the latest release, checks its SHA-256, puts it in `~/.local/bin` (no sudo), and adds the Claude Code plugin when Claude Code is installed. With no release for your machine it builds belay with cargo. `BELAY_VERSION`, `BELAY_INSTALL_DIR`, `BELAY_NO_SETUP`, and `BELAY_FROM_SOURCE` change what it does. CI tests it offline against a fake release (good install, bad checksum, missing release).
- **`belay install` / `belay uninstall`:** the Claude Code plugin, `belay status` as the status line (with a backup, never over another status line without `--force`), and a printed launcher alias, each shown and confirmed first. `belay doctor` says whether the plugin is installed and the status line is belay's.
- **`belay keep-awake [--for D | --pid P] [-- <cmd>]`** keeps the machine awake: `systemd-inhibit` on Linux, `caffeinate` on macOS, Windows' `SetThreadExecutionState` on WSL. It says first what it can hold off here, idle sleep and a closed lid, and never claims more. belay never runs `sudo` or changes a setting; it prints the fix (logind's `HandleLidSwitch`, `pmset disablesleep`, Windows' `LIDACTION`). `belay doctor` has a new `background` line with the same.
- `belay launch <agent> [args…]` starts any agent belay has a connector for. `belay launch claude-code` is the same as `belay claude`, which stays.
- **`belay mcp`:** an MCP server over stdio with `memory_search`, `memory_add`, `handoff_get`, `output_show`, and `why`. The plugin declares it, and its skill prefers these tools to the shell commands.
- **Memory:** `belay memory` lists, searches, adds, shows, approves, and drops memories in one store, each with its provenance. It reads notes, learned fixes, findings, and handoffs as memories; `belay memory migrate` copies them in once.
- **Memory in sessions:** at its end and before each compaction, a session keeps a handoff in memory: its task, files changed, last test, open failure, and the agent's own `belay handoff` text. The next session in the project starts with it, and with the best memories, within `recall_tokens` (new key, default 600). After a compaction, the agent gets a carry pack: its task, open failure, guard blocks, and the memories it was given. A failure that matches a `fix` memory gets it. The ledger records a `memory_recalled` action.
- **Packaging:** `cargo binstall` finds the release tarballs (`[package.metadata.binstall]`), and `packaging/homebrew/belay.rb` is a formula template for a tap. A release fails when the tag, the workspace version, and the plugin version disagree. CI runs the sandbox tests with bubblewrap.
- **`belay pause [feature]` and `belay resume [feature]`:** the kill switch for a live session, recorded in the ledger and shown by `belay status`. The agent's own `belay pause` and `belay resume` are denied.
- **The plugin teaches the agent:** a `belay` skill (handoffs, findings, denied edits, `belay show`, `belay why`) and slash commands `/belay:report`, `/belay:handoff`, `/belay:recall`, `/belay:remember`. Plugin version 0.2.0.
- **belay sees reads.** The plugin and `belay claude` also hook Read, Grep, and Glob after they run, and `SubagentStop`. Each read is recorded as an output (`belay show o-N`), never changed. `belay report` adds `Reads: N (R repeated)`: a repeat is the same content of the same file read again with no compaction in between. Read outputs no longer count as Bash output. `belay retro` sees reads in transcripts too, so its "Tool calls" count goes up. New ledger event `subagent_ended` (additive; older belay versions skip it).
- **Resuming continues tracking.** `belay claude --resume <id>`, `-c`, the picker, and `/resume` continue the earlier run's belay state: loop counts, open failure, blocked edits, pauses, shape levels, and the card's task. A restarted plugin daemon restores its own record. Ids go on across runs; `belay report`, `why`, `show`, and `undo` read the whole chain. The resumed agent gets the carry pack, not a fresh recall. `resume = fresh` (config) or `--belay-fresh` starts clean. New ledger entry kind `resumed` (additive); a resumed run's ledger starts with its `format` entry, numbered after the earlier run's last entry.
- **Sandboxes:** `belay sandbox run -- <cmd>` runs a command on a git worktree of the repo with a private home, under bubblewrap. It sees no other files of yours, no Docker socket or ssh agent, and on WSL no Windows. belay stops it past `sandbox_memory`, `sandbox_procs`, `sandbox_disk`, or `sandbox_wall`, and says why. Its changes are committed on `belay/sandbox/<id>` for you to merge. `belay sandbox list|show|diff|stop|rm|doctor`; `rm` is yours to run. With no way to build a sandbox, belay refuses and runs nothing. New config keys `sandbox_*`. New ledger events `sandbox_started` and `sandbox_stopped` (older belay versions skip them); the card has a `sandbox` field.
- **Seeing what belay does.** When belay acts, Claude Code shows you a one-line note (`systemMessage`), at most one per hook; the model never sees it. `report = quiet` (the default) shows warnings, `normal` adds summaries and other actions, `verbose` adds minor notes. `belay watch` prints notes as they happen. `belay status` reads `belay · N blocked · K tokens kept out · M memories`. When the agent exits, belay prints what it did, the tokens it kept out, and the handoff left. `belay report` says "would have" only for what the agent could not take. Notices are a new ledger entry kind (`notice`), so older belay versions skip those lines with a warning.
- **`belay brief`: what a session did, and what to check before you commit.** From belay's ledger and git, never the agent's summary. Changed: the files the session edited, with lines added and removed since its start snapshot. Checked: each test or check command's last result, and whether it ran after the last edit (✓ passed after the last edit, ⚠ not run since, ✗ failing). Look at, most important first, each with its evidence id: guard actions and whether you allowed them, verify nudges, CI and check config changed, dependency manifests changed (with added names), suppressions added, and files changed after the last passing run. `--markdown` prints a `## Summary by belay` section for a pull request; `--json` has stable keys. The exit summary now shows the brief's Changed, Checked, and Look at lines in place of the action counts. New MCP tool `brief` and slash command `/belay:brief`.
- **Skills from URLs:** `belay skill preview|add|list|update|approve|reject|remove`. belay fetches a skill from a GitHub tree or blob URL (pinned to its commit), a raw `SKILL.md`, a `.zip` or `.tar.gz` (refused if it has `..`, absolute paths, or links), or a local path. It checks the files, warns about risky text (download piped to a shell, base64 blobs, executables, requests to disable belay or permissions, "ignore previous instructions", hidden Unicode), and writes a `.belay-skills.lock` with the digest. An agent can only stage a skill; you approve it in your own terminal. `belay doctor` warns when installed files drift from the lock. New MCP tools `skill_preview` and `skill_stage`.
- **Undo:** belay keeps the working tree at the start and at the end of each agent turn, as private git refs. `belay undo t-N` rolls the files back to one, also what shell commands changed, without touching your index, HEAD, stash, or branches.
- **`belay usage`: where your tokens went.** Tokens (input, output, cache read, cache write) and an estimated cost from Claude Code's transcripts, for `--today`, `--week` (the default), or `--since DATE`, grouped `--by project|session|day`, or `--json`. Cost comes from a dated per-model price table, labelled est.; the new `prices` config key overrides it. For sessions belay recorded, it says how many tokens went into loops, after failing runs, and after repeated reads, and how many summaries kept out. It finds the 5-hour limit hits in the transcripts and estimates your usual 5-hour budget as the median cost before them (from 2 hits). `belay status` then adds `~N% of usual 5-hour budget`, from a cache in `usage-cache.json` (a few ms when warm).
- **Verify before done** (`verify = on`, new key, default `on`): when the agent ends its turn with files changed since the last passing run of its tests, belay keeps it going once: "Run it before you finish." Once per turn, never twice for the same state, never in a fleet session (the hub runs the check). Claude Code gets a Stop `decision: block`. New action kind `verify` (older belay versions skip those lines with a warning).

### Changed

- **Disk discipline for fleets.** In a Rust repo, fleet sessions and their checks build into `<belay home>/cache/<repo>/<slot>/target` (`CARGO_TARGET_DIR`), not into each worktree: one build per slot, warm across fleets, never shared by two running sessions. New key `build_cache = shared|separate|off` (default `shared`; `separate` uses `sccache` when it is on PATH). `belay fleet down` now removes the worktrees `belay fleet prune --yes` would, except where a task is not finished, and lists the rest. `belay fleet` and `belay doctor` show belay's disk use (fleets, sandboxes, sessions, cache) with the largest item, and warn above 10 GB. Sandboxes: `sandbox_build_cache = shared` binds one build cache per repo into its sandboxes (default `off`: sandboxes could pass build output to each other).
- **`belay doctor` for 0.2:** one command says whether belay will work here. Each line is `ok`, `warn`, or `fail`, with one sentence and the fix: Claude Code's version against the conformance records, the plugin's version against the binary's, the launcher alias, the status line, sandbox readiness (bubblewrap, user namespaces, WSL interop hidden, systemd scope or watchdog), skill drift and pending skills, 0.1 config names, and data size and age. `belay doctor --json` prints the same as JSON. It exits 1 only on a `fail`; the old `info` lines are now `ok` or `warn`.
- **`belay fleet prune --branches`** also deletes the merged `belay/<fleet>/*` branches of fleets that are down (`git branch -d`, never `-D`). Unmerged branches are listed with how many commits HEAD lacks, and kept. Sandbox branches are not touched. `prune --yes` is now the user's: refused outside your own terminal and denied to agents. `belay fleet` no longer lists fleets that are down and pruned; `belay fleet --all` does.
- **The guide follows the CLI.** A test (`crates/belay-cli/tests/guide.rs`) fails when a visible command or subcommand is missing from the guide's command reference, or a config key from § Config. The guide's sections are in a new order: what belay does for one session (guard, loops, verify, summaries, memory, resume, undo) comes first, then seeing it, sandboxes, skills, sessions, and fleets.
- **Memory respects the agent's own:** belay reads the CLAUDE.md files Claude Code loads and its auto-memory index, and never writes them. A memory they already state is not recalled at the start or in the carry pack; the `memory_recalled` reason says how many were left out. `belay memory add` refuses one with `already in CLAUDE.md (line N)`. The plugin skill says conventions go in CLAUDE.md, and belay memory is for what happened.
- **Ledger format 2.** A pause or resume is a `feature_changed` entry; `mode_changed` and the session's `mode` are no longer written. 0.1 ledgers still read, and their reports say "recorded in look mode (0.1)".
- **No more modes.** Look mode is gone: belay always acts within what the agent supports, and records why. Each feature has its own config key: `guard = deny|warn|off` (default `deny`), `loops`, `shape`, `memory` (was `learn`), `awareness` (was `fleet`), all `on` by default; `commons` (`off` by default: other sessions' messages and handoffs do not reach the agent, yours always do); `wrap_tests` (now `false` by default); and `report = quiet|normal|verbose`. Session cards are kept whatever `commons` says.
- **Old config and flags still work, with a warning:** a `look` value reads as `on`; `learn` and `fleet` map to `memory` and `awareness`; `plugin_mode`, `--belay-mode`, and `belay fleet up --mode` are ignored. `belay mode` says how to pause instead. Fleet sessions run with `guard = deny` and `commons = on`.
- **Sandboxes, part 2:** a sandbox is now its own clone of the repo (`git clone --shared`), so git works inside; it no longer uses a git worktree. belay commits leftover work inside the sandbox and fetches the branch with git's sending side also inside, so nothing in the clone's `.git` (hooks, config, filters) runs on your machine; belay's undo snapshots and audits skip a sandbox's clone. `belay sandbox claude` runs a whole Claude Code session in a sandbox, supervised by belay from outside (`--id S --resume <id>` goes on in it). `belay sandbox task "<prompt>"` runs a headless follow-up there and prints its result, branch, files, audit, and limits; agents may run it too, at most `sandbox_tasks_per_hour` (4) per session, stopped past `sandbox_task_tokens` (2M). MCP tools `sandbox_run` and `sandbox_task`. `belay sandbox doctor` has a probe for code planted in the clone's `.git`. Sandboxes made by the earlier, worktree-based build are refused: `belay sandbox rm` them.
- **Tokens kept out** in `belay report` (new line), `belay status`, and the exit summary is the sum of original − summary over summaries that reached the agent. Summaries whose reply came too late no longer count.

### Fixed

- **The test guard no longer flags removing a duplicate test.** Deleting one of two identical copies of a test (a merge often leaves one) read as "tests removed". A copy that stays still runs, so nothing is taken away. Removing the last copy is still flagged.
- **Guard precision.** Built from the false alarms of a real project. The guard no longer flags a new or empty file, a file outside the project, a skip under a runtime condition (`skipif`, `skipIf`, `skipUnless`, or `pytest.skip` in an `if` or `except` block), or a skip on a test the edit adds. It ignores a loosened tolerance that has a comment saying why, and a raise of less than tenfold. A relative tolerance of 1 or more is still flagged. Focus markers match each framework's syntax, so `model.fit(` in Python no longer counts. Tests moved to another file within one shell command or one turn are not a removal. An edit that only removes whole tests now warns instead of denying. A later move withdraws the warning with a `guard_withdrawn` judgment, a new judgment name in the ledger. A corpus in `fixtures/guard/real/` checks precision and recall.
- `belay retro` and `belay report` say "test runs are not wrapped (wrap_tests = off)" instead of a wrapped count of 0 when wrapping is off.
- **No stale worktree-overlap notices.** A peer's edit no longer draws "merging both branches will conflict" once its version of the file is in this session's HEAD, or once the peer has ended and its worktree is removed. A notice about a peer that has ended says so, once per file. belay checks this off the hook path, with one git call per new peer edit or HEAD move. New peer activities `merged` and `removed` in the ledger (older belay versions skip those lines).
- **Fleet hubs survive their terminal, and usage limits.** `belay fleet up` and `restart` start the hub detached (double fork, `setsid`, stdin from `/dev/null`, output to `hub.log`): closing the terminal or a SIGHUP to its shell no longer stops the fleet. A usage limit no longer counts as a failed attempt. When its message gives a reset time in UTC, the fleet resumes on its own 2 minutes after it; `belay fleet status` shows `paused until 02:32 UTC (usage limit)`. A task whose session stopped before it was done (limit, crash, hub restart) retries in the same worktree, and the new session is told the earlier partial work is there. New fleet ledger records: command `resume_at`, work `resumed`; the `usage_limit` event has `resets_at_ms` and `spawn` has `worktree_of` (older belay versions skip unknown lines and fields).
- **macOS build:** belay compiles on macOS again. The pidfd calls in the sandbox watchdog are Linux-only; other systems signal with `kill`.
- **Sandbox doctor:** the fork bomb probe counts a refusal by the systemd scope's task limit as contained, as well as a watchdog stop. A bomb that runs to the end is still reported as escaped.
- **Upgrading belay during a live session no longer breaks test runs.** A session started before the upgrade wrapped test commands through its own binary, which the upgrade had replaced, so every wrapped command failed to start. belay now wraps only through a binary that is still on disk, and otherwise lets the command run as written.
- `belay doctor` points to `belay config migrate` for 0.1 config names.
- **A session could hang on exit and lose its handoff.** When belay wrote the session card at the same moment the session ended (you quit Claude Code, the agent stopped, or an idle session timed out), the two could wait on each other forever. The next session then saw the old one as still running and got no handoff. Every exit path now takes the locks in one order.
- Skills from `.tar.gz` archives are read on macOS (bsdtar's listing differs from GNU tar's); links, devices, and traversal are still refused before extracting.
- Outside git, a project's root and its project key are spelled the same when the path goes through a symlink (macOS `/var`).

## 0.1.0

The first public release. belay supervises Claude Code through its hooks. It runs on Linux and WSL; macOS builds exist but are untested.

- **Look mode (the default)** records every tool call, output, and edit, and what belay would do, without changing what the agent sees. `belay report`, `belay why`, `belay show`, and `belay retro --all` (over past transcripts).
- **Optimize mode** lets belay act:
  - **Test guard:** it denies edits that weaken tests (assertions removed, skips added, expected values changed to the failing actual, tolerances raised, always-true asserts, rewritten golden files) until you run `! belay allow`. `.belay.toml` protects more paths.
  - **Loop detection:** it tells the agent when the same failure survives three rounds of edit-then-run, or when an edit undoes the one before.
  - **Faithful summaries:** long test output is cut to what matters, keeping every failure line. The original stays one command away.
- **Sessions that see each other:** a board of live sessions (`belay sessions`), messages (`belay msg`), shared findings (`belay share`, `belay ask`), handoffs to the next session (`belay handoff`), and notices when another session edits the same file or runs git under you.
- **Learned fixes:** a failure that a full run then passes is remembered, and the next session that hits it is told how it was fixed.
- **Fleets:** `belay fleet up` runs a team of headless sessions in their own worktrees. It has a task board, check-gated tasks, budgets, nine presets, and a merge plan.
- **Audit (experimental):** `belay audit` lists what a diff did to tests and checks. It also runs as a GitHub Action.
- **A Claude Code plugin**, for those who keep typing `claude`.
